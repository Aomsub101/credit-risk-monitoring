## 2. What goes where

| Folder | Holds | Rule of thumb |
|---|---|---|
| `notebooks/` | Exploration, charts, reasoning, conclusions | A notebook **tells the story** and calls functions. It is not the source of truth for logic |
| `src/credit_risk/` | Functions and classes reused by more than one notebook, by scripts or by the app | **Promote** code from a notebook to `src/` as soon as a second place needs it, or when it computes a number you will report |
| `scripts/` | Thin CLI wrappers that run `src/` functions in order | No business logic here; just argument parsing and calls |
| `data/` | Raw, interim, processed datasets | Raw is read-only. Interim/processed are always regenerable |
| `models/` | Fitted artifacts + metadata | Regenerable, so gitignored |
| `reports/` | Tables, figures, metrics, monitoring reports | Small and committed, so reviewers see results without running code |
| `app/` | Streamlit UI | Loads artifacts; never trains |
| `tests/` | pytest tests for `src/` | Test the maths (WoE, KS, PSI, scaling) on tiny hand-made data, and test the leakage guard |
| `docs/` | Planning, guides, model documentation | Living documents; PROGRESS.md is updated every step |

## 4. How your existing notebook fits

`[01]_extract_data.ipynb` was moved to **`notebooks/01_extract_data.ipynb`**. Its contents are still exactly as you left them, including your uncommitted change.

- It currently loads Home Credit's `bureau.csv`. In Step 1 you will **rewrite it for Lending Club**: read the header, select columns, set dtypes, parse `issue_d`, save `data/interim/loans.parquet`.
- Its job stays the same ("extract data"), so the name and number still fit.
- The path logic (`os.getcwd()` + a Windows backslash path) will break now that the notebook lives in `notebooks/`. Fixing it properly is a Step 0 task (paths in `config.py`).
- Once the loading code works, promote it to `src/credit_risk/data.py`. The notebook then becomes a thin demonstration of that function.

## 5. Configuration and seeds

All tunable choices live in `src/credit_risk/config.py` so that a reviewer can find every assumption in one file:

- `PROJECT_ROOT` and derived paths (`RAW_FILE`, `INTERIM_DIR`, `PROCESSED_DIR`, `MODELS_DIR`, `REPORTS_DIR`)
- `SEED`
- Date windows (`DEV_END`, `VALID_START`, `OOT_START`, `OOT_END`, `MONITOR_START`, `MONITOR_END`)
- Target mapping (`BAD_STATUSES`, `GOOD_STATUSES`)
- Scaling parameters (`PDO`, `BASE_SCORE`, `BASE_ODDS`)
- Monitoring thresholds (`PSI_AMBER`, `PSI_RED`, persistence rule)

A YAML config file would also work, but a Python module needs no extra dependency and gives you autocomplete. Keep one source of truth either way.
